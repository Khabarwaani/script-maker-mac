# Script Maker 2.0

Tracking spec: [#147](https://github.com/Khabarwaani/script-maker-mac/issues/147).

## Integration gate

Implementation PRs target `revamp/2.0`. This exception applies only to #147.
The primary checkout stays on `develop`; implementation uses separate worktrees.
Do not merge the revamp into `develop` or `main` until remote CI passes, the user
has tested the exact release-candidate commit, and explicit approval is recorded.
Green CI alone does not authorize integration or release. No release tags during
candidate testing. The version remains unchanged until release preparation.

## Work packages

- [ ] Agent session ownership, serialization, cancellation, and cleanup.
- [ ] Throwing persistence, atomic mutations, and legacy-data regression coverage.
- [ ] Shared typed agent defaults, workspace overrides, and settings migration.
- [ ] Remove obsolete generation workspace, server/sample mode, and merge action.
- [ ] Extract shared controls/models; preserve historical generation metadata.
- [ ] Dependency injection, settings boundaries, and Pipeline orchestration.
- [ ] Test-fixture/resource cleanup and current architecture documentation.
- [ ] Installable candidate, upgrade verification, and user acceptance.

existing stories (including previously seeded examples), Script Detail items,
refinement histories, credentials, and media. Never seed new sample stories.

destinations. Record unavailable capabilities and obtain acceptance of test gaps.

and rerun CI/affected checks before requesting approval for the final commit.
Only after approved integration, verify the integrated `develop` app using Xcode's
default DerivedData location. Release through a separately approved PR to `main`;
tag only the approved main commit and verify the DMG asset.
