## Acceptance checklist

Automated evidence must come from the current implementation head, including all
integrated develop changes. Local test runs are only CI-failure diagnosis; CI remains
the verification gate. Record final checks on the implementation PR.

- [ ] Current-head remote CI passes architecture checks, compilation and all service/view-model tests.
- [ ] UI smoke verification covers every workspace, Settings and Agents & Instructions.
- [ ] User tests the complete change, including available terminal/on-device providers.
- [ ] Upgrade testing uses copies of existing stories, scenes, histories, receipts and media.
- [ ] Real upload checks use test destinations; document unavailable capabilities and get acceptance of gaps.
- [ ] Refresh against latest develop and rerun affected checks before final approval.
- [ ] Explicit approval is recorded for the complete tested commit before integration.

The acceptance artifact uses a separate bundle identifier, preferences, media namespace
and Keychain service. Production keeps its original paths/service. Never infer successful
persistence or verification from a swallowed error. Unknown historical stage keys remain
visible. Failed writes keep the last saved content and editable draft.

After approved integration, verify integrated develop with default DerivedData. Only then
prepare the version/build bump and release notes. Release through a separately approved
PR to main, tag the approved commit, and verify the published DMG. Issue #147 stays open
until the complete acceptance gate is satisfied.
