# Git / PR

Any code change. Start from `origin/develop`. End: branch pushed, PR open, merge only after user approval.

1. No push or merge to `main` or `develop` (`GH013` / `.githooks`). PR only.
2. No force-push (`--force` / `--force-with-lease`) — emergency only, with explicit user permission each time.
3. Branch names: `feature/<name>`, `fix/<issue>-<name>`, `refactor/<name>`, `chore/<name>`.
4. Scripts, not raw multi-step git:

| Task | Command |
| :--- | :--- |
| Sync develop | `./sync_develop` |
| Branch (links issue in GitHub) | `./create_branch <prefix>/<name> [--stash]` |
| Stash | `./stash [push [msg] | pop | list | drop]` |
| PR (opens draft, links issue) | `./open_pr -t "..." [-b "..."] [--ai "..."]` |
| Server CI status | `gh pr checks` |
| Mark ready for review | `gh pr ready [<pr>]` |
| Tests (server CI fail only) | `./runut` |
| Resolve review | `./resolve_comment <pr> [reply] [--ai "..."]` |
| Merge | `./merge_pr <num>` |

5. UT runs on the git pipeline — do NOT run tests locally before opening a PR.
6. Test fail: [`failure.md`](./failure.md). Do not edit a broken script or test; `gh issue create`.
7. Ready for review vs failure triage:
   - Server CI passes (green) → `gh pr ready`.
   - Server CI fails (red) → validate locally with `./runut`, fix, push, then `gh pr ready` once green.
8. PR body: omit `-b` to auto-derive from commit subjects with `(#N)` (#359, #481).
9. Read-only fallback: produce prefilled compare/issue links if `gh` lacks write access.
10. Attribution: pass `--ai "<name>"` (or `AI_NAME="<name>"`) to `./open_pr` / `./resolve_comment`. For issues (`gh issue create`), append `_Generated by <name>_` or `_Generated by human and <name>_`.
11. Review threads: fix, push, then `./resolve_comment <pr> "Addressed in <sha>: <summary>"`. Never resolve only in the GitHub UI.
12. Stop before merge. Show GitHub PR URL, diff, tests, and `./merge_pr <num>`. Merge only after user approval.
13. Labels: AI must NEVER add or remove the `next release` label — only the user manages it. AI must never ADD the `code completed` label (user only), but AI MAY REMOVE `code completed` when a new bug/issue is reported against that same feature — and must add the `reopened` label in that case.

```bash
./create_branch <prefix>/<name> [--stash]
git add <files>
git commit -m "<type>: <desc>"
./open_pr -t "<type>: <desc>"
# verify server CI: gh pr checks
# if green -> gh pr ready; if red -> ./runut, fix, push
./merge_pr <num>
```
